Bug: `src/mcp.rs`'s `run()` (the stdio `rtok mcp` server) calls `plugins::graph::lsp::shutdown()` at stdin EOF, but `call()` — the one-shot `rtok mcp --call <tool> --json <args>` used by hosts that shim MCP through a plain CLI call (the pi host, T70.3) — never did. The LSP session lives in a `static SESSION` in `src/plugins/graph/lsp.rs` that is never dropped on its own, so with `graph.backend = "lsp"` every `--call` of a graph tool (`symbol`/`callers`/`impact`/`outline`/`explore`) left rust-analyzer/clangd/typescript-language-server/dart running as an orphan after `rtok` exited.

Fix: an RAII `LspGuard` (`#[cfg(feature = "graph")]`, mirroring the `run()` gate) declared as the first statement of `call()`; its `Drop` calls `lsp::shutdown()`, so it fires on every exit path — success, `Err`, or an early `?` — the same helper `run()` already used, no new logic.

Tests: `tests/common/fake_lsp.rs` (unix-only) — a `clangd` script first on `PATH` that answers `--version` and, in server mode, speaks minimal LSP over stdio (Content-Length framing), replying immediately to `initialize` and `workspace/symbol` so `lsp.rs`'s 40 s `READY` poll never actually waits, and to a `BoomTrigger` query with a JSON-RPC error to exercise the error path. Liveness never touches a real pid: the fake takes an exclusive `flock` on a lock file in the test's temp dir and holds it for its whole life; a test proves the fake is gone by trying to acquire that same lock itself (`rtok_sys::try_lock_exclusive`, the same `flock(2)` primitive already used elsewhere in this codebase for file locking) — the OS releases the lock the instant the fake's file descriptors are torn down, for any reason. The fake exits on an explicit LSP `exit` notification immediately, on plain stdin EOF after a short grace period (long enough that a missing shutdown still shows up as "still alive" within the tests' ~2 s check), and unconditionally after a ~15 s hard self-timeout, so a failing test can never leave a process running. `tests/mcp_call_lsp_orphan.rs`: `call_shuts_down_lsp_after_a_successful_tool_call`, `call_shuts_down_lsp_after_a_tool_call_that_errors` (the fake LSP has already started and initialized when the call fails — exactly the path the old code missed), and `run_stdio_server_shuts_down_lsp_at_stdin_eof` as a regression guard for `run()`'s existing shutdown-at-EOF path. All three spawn the real `rtok` binary with an isolated `RTOK_HOME` (`graph.backend = "lsp"`), a workspace with `compile_commands.json` and no `Cargo.toml` (so `lsp::pick` chooses clangd), and `PATH` prefixed with the fake; after `rtok` exits they poll the lock file for up to 2 s. Before the fix, `call_shuts_down_lsp_after_a_successful_tool_call` failed with `fake LSP server still held its lock 2s after \`rtok mcp --call\` exited` (verified by re-running the test against a build with the `LspGuard` line removed).

Check: `cargo nextest run --test mcp_call_lsp_orphan` 3/3; `just check` green.

Complexity: 2/5.
