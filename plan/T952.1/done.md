Finishing a task in an rtok worktree takes five manual steps today (commit, push, `gh pr create`, auto-merge, unlock), and agents skip some: the worktree stays locked and its branch never reaches a PR. One command does them in order from inside the worktree. It never closes the task: the task closes only after the PR is merged (T952.2).

Done: `rtok worktree finish [path] [-m <msg>] [--repo <owner/name>] [--no-auto-merge]` and MCP `worktree_finish`. It refuses the main checkout, a detached HEAD, a branch with no own commits and nothing to commit, and another agent's lock. A dirty tree is committed whole (`git add -A`; message `-m`, else `<task>: <branch slug>`), refused when a staged path is a credential file (`read::roots::is_secret`). Then `git push -u origin <branch>`, reuse the open PR for the branch or `gh pr create --fill-first`, `gh pr merge --auto --squash` unless `--no-auto-merge` (a refusal there is a warning), and last `git worktree unlock` of our own lock, so a failed step leaves the lock in place. The claim row stays: a live agent's worktree is still never collected.
