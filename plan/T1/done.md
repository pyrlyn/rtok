# T1. Done

PR: https://github.com/pyrlyn/rtok/pull/253

## What was done

- `.github/workflows/ci.main.kts` (github-workflows-kt, as in `pyrlyn/octo`) generates `.github/workflows/ci.yml`. A `check_yaml_consistency` job fails when the YAML is edited by hand. Triggers: every pull request and push to `main`.
- `macos` job: `macos-15` (Apple Silicon), `./gradlew macosArm64Test cliTest e2eTest`.
- `linux` job: `ubuntu-latest`, `./gradlew -Prtok.allTargets=true linuxX64Test cliTest e2eTest -x ktlintCheck -x detekt --continue`.
- Both jobs: `jdx/mise-action` installs the tools from `mise.toml`; `pyrlyn/packages` is checked out at tag `0.0.1` into `packages/`, with `SHARED_SETTINGS_DIR`, `KOTLIN_WASM_DIR`, `KOTLIN_SNAPSHOT_DIR`, `KOTLIN_WEBGL_DIR` and `KOTLIN_KIT_DIR` set (the last one for T2); Gradle is cached by `gradle/actions/setup-gradle`, `~/.konan` by `actions/cache`. Every action is pinned to an exact release. The R2 remote build cache stays off (no secrets).
- Linux needs a warm `~/.konan`: `buildSrc/CrossCc.kt` looks for Kotlin/Native's clang and gcc sysroot while Gradle configures, and only linking a Kotlin/Native target downloads them. `scripts/ci/konan-bootstrap` is a throwaway project the Linux job links (x64 and arm64) first. Fixing `CrossCc` itself would not help: the C compile needs the toolchain before any Kotlin/Native task runs.
- Lint is excluded on Linux: every test task depends on `ktlintCheck` and `detekt` of all source sets, macOS ones included, which pull in the macOS C compile (`xcrun`). The macOS job lints.

## Fixes the first CI runs forced

- `rtok-e2e/.../GuardCheckE2eSpec.kt`: named the magic number `400` (detekt `MagicNumber`, merged with #250; it stopped the macOS job before any test).
- `ktlintFormat` of `rtok-sys` and `http-ktor` `linuxMain` sources (formatting only; no Mac build lints them).
- `rtok-e2e/.../LogsE2eSpec.kt`: `chmod` mode via `.convert()`; `mode_t` is `UInt` on Linux, so the e2e suite did not compile there.

## Linux link error (found on the way, fixed)

`:rtok:linkDebugExecutableLinuxX64` and `linkDebugTestLinuxX64` failed with `ld.lld: duplicate symbol ...clikt.core#selfAndAncestors` (the K/N static caches of clikt and clikt-mordant both define it). `kotlin.native.cacheKind.linuxX64=none` (commit 721c916) is ignored by Kotlin 2.4.21, which removed it in 2.3.20; `rtok/build.gradle.kts` now calls `disableNativeCache(...)` on the linuxX64 binaries instead and the property is gone.
