Done: new `src/plugins/graph/health.rs`. `Health::tick(rt, projects, probe, now)` is one round; the clock and the capability probe are arguments, so the tests step a fake clock and need no language server. A round checks each project of the scope: the root (a `stat` on its own thread with a 2 s timeout: gone under an existing parent is `missing`; parent gone too, an I/O error or no answer is `unreachable`), the manifest references (`project::refs::discover` warnings ending in "not found" are `link broken`) and the capability record (`backend down`). A finding must be seen by two rounds in a row to raise an alert and a missing finding by two rounds in a row to clear it (a one-round blip never alerts); a cleared `missing` or `unreachable` project is re-indexed. Alerts are mirrored per project into `plugin_state` (`alerts:<root>`), and a restarted loop takes over what an earlier run stored so it still clears. The backoff for a broken server is 60 s, doubled per retry, capped at 900 s; a server that appears on `PATH` after the record was made is picked up in the same round. `run` wraps rounds in `catch_unwind` and sleeps in 10 ms steps against `stop`, so it fails open and never blocks a request (requests still never call `reprobe`, T337). `rtok mcp` starts it for its working directory's scope (links followed with missing projects kept, unlike `Store::project_scope`) and `rtok web` for the whole registry. Grouping is per kind ("b, c missing since 14:02 (2 projects)"), a project linked only through others names the chain ("a to b to c: c missing"). The MCP `symbol`, `callers`, `impact`, `outline` and `explore` answers get `notice: ... ; results exclude b` lines in front when the scope holds an alert. `rtok doctor` prints a `graph alerts` section and `--json` carries `graph_alerts`; `rtok graph projects --json` and `/ws` carry `alerts` per project (`ws.schema.json` blessed, `snapshot.gen.ts` regenerated). `Capability` gained `down` (the server worked, then broke) so a server that was never installed is not an alert, and `capability::held` lets the check retry only the record its own process holds. `[plugins.graph] alerts = true` and `health_check_interval_s = 60` are in `default.toml`, `lib.rs`, the goldens and `docs/config.md`; `docs/lsp.md` has a "Health check and alerts" section (en, ru, uk).

Deviations: The retry of a broken server is the capability probe (binary on `PATH`), not a server spawn plus `initialize`: a second spawn would share the one cached session, its stderr file and its lock with the request path, which the health check must never wait on.
