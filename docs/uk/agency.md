# Agency: кросплатформний продукт

Це основний текст про **agency** для агентів програмування, що працюють над rtok.

## Платформи

**rtok — кросплатформний продукт.** Підтримувані платформи — це рівно
**Windows**, **macOS** і **Linux**. Він **мусить** і далі підтримувати всі три
як першокласні цілі.

**Не** додавайте, не документуйте, не налаштовуйте CI і не випускайте релізи для жодної іншої платформи. Не згадуйте
інші операційні системи як підтримувані, заплановані чи необов'язкові.

Ставтеся до кожної зміни так, ніби вона працюватиме на Windows, macOS і Linux:

- Шляхи, змінні середовища, оболонки, закінчення рядків і структура встановлення відрізняються
  між цими трьома; не покладайтеся на суто Unix-звички (`~/.…`, `sh`, символьні посилання,
  `chmod`) без варіанта для Windows.
- Хуки, MCP і `rtok proxy` — однакові інтерфейси на Windows, macOS і
  Linux; шляхи встановлення для хостів і поведінка повторного відкриття GUI все одно потребують покриття на
  всіх трьох (див. [agents.md](agents.md)).
- Реліз постачає `x86_64-pc-windows-msvc`, `aarch64-apple-darwin` і
  `x86_64-unknown-linux-gnu` (див. [release.md](../release.md)). Віддавайте перевагу виправленням, які
  тримають цю матрицю зеленою; не прибирайте й не оголошуйте м'яко застарілими Windows, macOS чи
  Linux без явного рішення користувача.
- CI, документація, скрипти й приклади, що працюють лише на частині з цих трьох,
  неповні, доки не охоплено відсутню(і) з Windows / macOS / Linux
  (або доки прогалину не задокументовано як відоме обмеження з відстежуваним
  подальшим завданням).

## Чим це не є

Цей файл **не** є матрицею «хост × модуль» ([agents.md](agents.md)) і не
замінює кореневий `AGENTS.md` (робочий процес, Checks, правила fail-open). Він
формулює платформний контракт, якого ці агенти мусять дотримуватися.
