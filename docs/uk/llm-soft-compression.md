# М'яке стиснення за допомогою LLM (P28)

**Статус: Пізніше / дизайн + екстрактивне стиснення випущено; LLM-напрям досі закритий перевіркою.**  
Лише дослідження й дорожня карта — цей документ не додає нової поведінки під час виконання.
Контекст гілки: `docs/batch-flex-pass` (дослідження економії токенів поряд із
Batch/Flex і маршрутизацією моделей).

Джерела задуму: `ideas.md` (I-21, “LLM soft compression (P28)”),
`plan.md` / `done.md` **P28** (T28.0–T28.2),
`src/plugins/compress/PLAN.md` (огляд D15), `roadmap.md` Later,
`docs/prompt-cache.md`, `docs/batch-flex.md`, `docs/model-routing.md`,
`research.md` §2 / §6.9 / §9.2.

## 1. Що тут означає «м'яке стиснення»

У rtok **м'яке стиснення за допомогою LLM** — це **необов'язкове, вимірюване переписування тексту в контексті
з попереднім архівуванням** (зазвичай старих тіл `tool_result`, уже доступних
через `expand <id>`), яке виконує **виклик моделі** (або невеликий
спеціалізований компресор), і **не**:

- квантизація KV-кешу / активацій усередині GPU провайдера
- attention sinks, ковзне вікно чи масштабування RoPE у стеку обслуговування моделей
- автоматичне ущільнення хоста (`PreCompact` / `preCompact`) — це територія T58.2 /
  контрольних точок
- **детерміноване екстрактивне** зведення, уже випущене в
  `plugins.compress` (T28.2 / T127)

«М'яке» = **подання** в промпті може відкидати чи перефразовувати байти;
**жорсткий** контракт (D4) зберігає оригінал у `~/.rtok/archive/`, тож
`rtok expand <id>` / MCP `expand` відновлює джерела, які неможливо згенерувати повторно.

### Уже випущено (не пункт «Пізніше»)

| Складник | Поведінка сьогодні |
|-------|-----------------|
| Архів без втрат + `expand` | Завжди ввімкнено для відфільтрованих/заархівованих даних |
| Екстрактивний ранжувальник `plugins.compress` | Типово **увімкнено** (`enabled = true`); працює лише коли `proxy.mode = "compress"`; без мережі / без LLM; рядки `Measurement` |
| Переписування в проксі з живою зоною / збереженням кешу | Старі результати інструментів зменшуються без змін system/tools/живого краю (`docs/prompt-cache.md`) |
| Режими стиснення виводу / прози | Екстрактивний + у стилі caveman (`modes`, порівняльні бенчмарки) |

Пункт досі відстежується в `ideas.md` (I-21) як **To add**, бо
**LLM-напрям** (клас LLMLingua або вилучення спостережень у стилі claude-mem
за явним прапорцем, Gate P28) — **не** типовий екстрактивний шлях.
T28.2 додав екстрактивну реалізацію й відклав LLM-екстрактор спостережень
для пам'яті.

### I-21 → P28 (задум дослівно)

З розділу Later в `ideas.md`:

## 2. Огляд підходів (що пасує проксі / середовищу виконання агента)

rtok — це проміжне ПЗ: хуки, MCP і особливо **`rtok proxy`** на синхронних
чат-протоколах. Він **не** володіє KV-кешем чи семплером моделі. Підходи
поділяються на три групи.

### A. Реалістичні для rtok (рівень HTTP / архіву)

| Підхід | Ідея | Придатність | Застереження |
|----------|------|-----|--------|
| **Семантичне зведення з попереднім архівуванням (обрано)** | Після архівування без втрат замінити блок у контексті структурованим зведенням (тип / заголовок / факти / файли); `expand` зберігає оригінал | **Основний механізм P28** (`compress/PLAN.md`) | Коштує токенів компресора; ризик для якості коду/diff |
| **Екстрактивне збереження/відкидання токенів/фрагментів (клас LLMLingua-2)** | Невеликий класифікатор оцінює токени; відкидаються малоінформативні фрагменти | Корисно як **локальний / офлайн**-напрям або базова лінія бенчмарку; ідею вже оглянуто; сам пакет Microsoft відхилено (D6) | Без втрат лише зі зворотним вказівником на архів; слабко працює з ідентифікаторами |
| **Вилучення спостережень → `memory`** | LLM після виклику інструмента пише нотатки; поступове розкриття | Необов'язкова половина T28.2; пов'язано з I-73 / I-79 «LLM-половина лишається в P28» | Хибні факти отруюють пригадування; типово вимкнено |
| **Хуки ущільнення хоста + id архіву** | Переживають зведення від провайдера | T58.2 (окрема картка); доповнює м'яке стиснення | Сам байтів не зменшує |
| **Маршрутизація моделей для викликів компресора** | Дешева модель для зведення / класифікації | Ортогональний важіль (`docs/model-routing.md`); використовувати для витрат **компресора**, а не для моделі, якою агент програмує | Потребує Check маршрутизатора; не плутати з Batch/Flex |

### B. Суміжні, але не «м'яке стиснення»

| Підхід | Чому це інший важіль |
|----------|-----------------------------|
| **Batch / Flex** | Змінює, *коли / за яким тарифним рівнем* передаються ті самі байти (`docs/batch-flex.md`). М'яке стиснення змінює, *скільки* байтів промпту надсилають синхронні протоколи. |
| **Sticky-префікс кешу промптів** | М'яке стиснення **ніколи** не має переписувати system / tools / живий край (T14.5 / D). |
| **Семантичний кеш відповідей (P31)** | Кешує **відповіді**, а не зменшує промпт; ризик хибних влучань. |
| **TOON / форматувальники cmd / tools_rewrite** | Детерміновані переписування без втрат або за списком дозволених — уже у v0.1. |

### C. Поза межами rtok (внутрішня будова моделей, що обслуговуються)

| Підхід | Чому rtok не може випустити це як плагін |
|----------|-------------------------------------|
| **Стиснення / витіснення KV-кешу** | Живе у vLLM / TensorRT-LLM / провайдера; rtok ніколи не бачить тензорів |
| **Квантизація активацій / ваг для інференсу** | Обслуговування на етапі розгортання; не проміжне ПЗ проксі |
| **Attention sinks / ковзне вікно / LongRoPE** | Архітектура моделі / конфігурація обслуговування |
| **Спекулятивне декодування / Medusa** | Затримка, а не економія токенів промпту в протоколі агента |

Якщо провайдер надає прапорець API для «стисненого контексту», вважайте це
експериментом у **Wire prepare** з Measurement — це все одно не м'яке стиснення KV
всередині rtok.

## 3. Механізм, який зберігаємо (рішення)

Підтверджуємо `src/plugins/compress/PLAN.md`:

1. **Напрям без втрат** — без змін, завжди доступний.
2. **Екстрактивний напрям** — випущено; детермінований; типово ввімкнений, коли
   `proxy.mode = "compress"` і `plugins.compress.enabled`.
3. **LLM-напрям (Пізніше)** — типово **вимкнений**; лише після того, як існує рядок архіву;
   лише за критеріями придатності, що відповідають архіву (наприклад, старше за N ходів або понад
   обмеження розміру); ніколи не торкатися кешованого префікса; записувати `Measurement` з
   `bytes_in` / `bytes_out` / `tokens_spent` / `plugin = compress` (або
   `memory` для екстрактора спостережень).
4. **Gate** — `rtok bench` у стилі P9: **вартість за пройдену задачу ≤** базової лінії
   без втрат (з урахуванням токенів компресора); частка пройдених задач не має падати;
   `expand` відновлює оригінали, які неможливо згенерувати повторно.

Відхилено (як і раніше): обгортання Microsoft LLMLingua / воркера claude-mem /
headroom (D6); LLM, увімкнений типово; обрізання без архіву; переписування префікса.

і **нижче або поряд** із вимірюванням маршрутизації моделей — м'яке стиснення витрачає
токени, щоб заощадити токени; Batch/Flex і маршрутизація часто дають дешевші перші

## 6. Ризики й спростування

1. **Вартість за пройдену задачу зростає** з урахуванням токенів компресора → не випускати.
2. **`expand` не спрацьовує** на результатах tool/read/diff, які неможливо згенерувати повторно → порушення D4; блокувати.
3. **Заявлена економія без `Measurement`** → D1; такої економії не існує.
4. **Скидання кешу промптів** через переписування system/tools/живих ходів → регресії частки влучань у `docs/prompt-cache.md`.
5. Якість на **тексті, схожому на код** (research.md §6.9 / уроки caveman) → вимагати golden-фрагменти, які «треба зберегти», у Фазі 1.
6. **Плутанина між екстрактивним (увімкнено) і LLM (Пізніше)** у документації/маркетингу → цей файл і назви в `ideas.md`.
