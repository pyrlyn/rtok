# Огляд

rtok — це один бінарник на Rust, який зменшує кількість токенів, що їх спалює ШІ-агент для програмування. Кожен
метод скорочення токенів — це плагін за єдиним трейтом, а до цих плагінів ведуть три
інтерфейси:

| Інтерфейс | Точка входу |
|---------|-------------|
| Хуки Claude Code | `rtok hook <event>` — JSON на stdin, JSON на stdout |
| MCP-сервер | `rtok mcp` — `read`, `search`, `tree`, `expand`, `mem_*`, інструменти графа |
| API-проксі | `rtok proxy` — проміжний вузол `ANTHROPIC_BASE_URL` / `OPENAI_BASE_URL` |

> [!WARNING]
> **Статус: v0.0.1.** Усі десять плагінів реалізовано на всіх трьох інтерфейсах, разом із
> вимірюванням, походженням конфігурації, експортом OTLP і вебпанеллю. *Не* зроблено
> головне число: закомічений A/B-бенчмарк запускався лише офлайн, тому він показує
> нулі для обох конфігурацій. Сьогодні rtok стверджує «вимірювано», а не «дешевше».

## Навіщо він існує

Типове налаштування Claude Code нашаровує кілька інструментів, кожен з яких стискає вивід Bash, кешує
читання й вставляє контекст на початку сесії, — і кожен заявляє 60–95 % економії, яку ніхто
не вимірює від початку до кінця. Якщо виміряти, такий набір економить 3–40 % і коштує приблизно 3 K вставлених
токенів за хід.

rtok замінює цей набір одним бінарником, який працює як один хук на подію, надає
одинадцять MCP-інструментів за ~143 токени опису на хід замість ~8 600 на дев'ять серверів, стоїть як
один проміжний вузол проксі, що записує реальне `usage`, і веде одну таблицю вимірювань, щоб `rtok stats` міг
сказати, що насправді змінилося. Повний розбір інструмент за інструментом, зокрема там, де rtok відстає, —
у [Порівнянні](comparison.md).

Кожен плагін написано з нуля в цьому репозиторії. rtok ніколи не запускає, не лінкує й не читає
інструментів, які він замінює.
