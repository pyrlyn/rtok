# Початок роботи з rtok

`rtok` зменшує контекст, який мусять нести ШІ-агенти для програмування. Один бінарник на Rust, три
інтерфейси: хуки Claude Code, MCP-сервер і API-проксі. Кожне скорочення
вимірюється; скорочені дані можна отримати назад за id.

## Встановлення

Для macOS (Apple silicon) і Linux x86-64 є готові бінарники.
Інсталятор написано на POSIX `sh`, він кладе `rtok` (і `rtok-update`) у `~/.cargo/bin`.

```bash
curl --proto '=https' --tlsv1.2 -LsSf \
  https://github.com/pyrlyn/rtok/releases/latest/download/rtok-installer.sh | sh
```

Або за допомогою [ketch](https://github.com/pyrlyn/ketch), з тих самих архівів релізу:

```bash
ketch install pyrlyn/rtok
```

Хуки спершу пробують швидкий клієнт `rtok-hook`. Коли менеджер пакетів лінкує в `PATH` лише `rtok`, команди `rtok mcp`, `rtok hook --serve` і `rtok agents install` створюють посилання на `rtok-hook` поруч у тому самому каталозі з `PATH` (unix, у міру можливостей; наявний чужий файл не чіпають).

Із вихідного коду (інструментарій закріплено в `mise.toml`):

```bash
git clone https://github.com/pyrlyn/rtok && cd rtok
mise install
mise exec -- cargo install --path .
rtok --version
```

## Перший запуск

```bash
rtok config init      # записує ~/.rtok/config.toml
rtok plugins          # id, увімкнено, інтерфейси
rtok doctor           # перевіряє хуки, MCP-сервери, ланцюжок проксі
```

`rtok doctor` варто запустити *до того*, як ви щось установите: він оцінює вартість
хуків і MCP-серверів, які у вас уже є, зокрема токенів опису, що надсилаються повторно
на кожному ході.

Підкоманда, плагін якої не вкомпільовано, виводить `not implemented` і завершується з кодом
0, тож урізаний або напіввстановлений rtok ніколи не блокує агент-хост.

## Підключення до Claude Code

```bash
rtok agents install claude --dry-run
rtok agents install claude
rtok agents uninstall claude
```

`--dry-run` виводить записи хуків і нічого не змінює. Встановлення створює резервну копію кожного
файлу, який записує. Інші хости (`cursor`, `codex`, `opencode`, …) описано в кореневому
[README](../../README.md).

## Чотири інваріанти

1. **Fail open.** Хук завершується з кодом 0 за ≤ 10 мс навіть у разі помилки, з незміненими вхідними даними.
2. **Типово без втрат.** Усе скорочене можна отримати через `rtok expand <id>`.
3. **Економії, яка не є рядком `Measurement`, не існує.**
4. **Вставлений контекст не перевищує бюджету й лишається побайтово стабільним**, тож ніколи не ламає кеш промптів.

## Де що лежить

```text
~/.rtok/config.toml     конфігурація (`RTOK_HOME` перевизначає каталог)
~/.rtok/rtok.db         SQLite — вимірювання, індекс архіву, пам'ять
~/.rtok/archive/        сирі дані, адресовані за id для expand
<git root>/.rtok.toml   необов'язкові перевизначення для окремого проєкту
```

## Застереження

- Кількості токенів у `rtok stats` — це оцінки (див. `src/tokens.rs`) плюс реальні рядки `usage`
  з проксі. Справжній рахунок — лише рядки з проксі.
- Закомічений A/B-бенчмарк запускався лише офлайн, тому він показує нулі для
  обох конфігурацій. Перезапустіть його на живому трафіку, перш ніж обирати
  конфігурацію на його слово.
