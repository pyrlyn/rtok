# PDF-рендерер отчёта (T22.0)

`rtok report --format pdf` нужен PDF-рендерер, слинкованный в единый бинарник (D1). Эта страница —
обзор D15, которого требует задача: три кандидата, оценённые по тому, что они делают с релизным
бинарником, который контролирует P17, сохраняют ли они истинным утверждение «один статический бинарник без зависимостей времени выполнения» и
получаются ли HTML и PDF из одного документа (D24), а не из двух вёрсток. Каждый размер
ниже измерен на этой машине: черновые строки — 2026-09-09, в `/tmp`, без
изменения `Cargo.toml` репозитория; строка со слинкованным рендерером — 2026-09-10, из worktree этого репозитория.

## Задача

У отчёта один источник содержимого — операторская модель D23 — и три представления: Markdown,
HTML, PDF. Markdown и HTML ничего не стоят при линковке. PDF-рендерер — единственный кандидат, который
может добавить реальные байты к бинарнику, ради сохранения малого размера которого и существует проверка P17 (её записанная база: релизный
`rtok` 19 157 712 B (18.27 MiB), 2026-09-04, `done.md` P17 и `research.md` §2; dist-сборка
17.4 MB, 2026-09-07, `research.md` §2 "Where a hook's milliseconds go"). P17 не публиковала предел в байтах;
она опубликовала числа и цель — «то, что скачивает пользователь, перестаёт расти вместе со
списком зависимостей». Поэтому вопрос не только в том, какой рендерер победит, но и в том, каков прирост у победителя,
указанный вместе с командой, которая его дала.

## Альтернативы

| Кандидат | Версия | Дата | Что делает хорошо | Что делает плохо |
|-----------|---------|------|------------|------------|
| `typst` как библиотека (+`typst-pdf`, `typst-layout`, `typst-assets`) | 0.15.1 | 2026-09-09 | один исходник разметки компилируется в постраничный PDF; экспорт HTML (`typst-html`) есть в том же дереве; настоящий перенос строк, таблицы, оглавление | измерено **+44.35 MiB** к релизному бинарнику — в 2.3 раза больше всего сегодняшнего бинарника `rtok`; полноценный движок вёрстки (image 0.25.10, comemo, fontdb) для отчёта из таблиц и коротких выводов |
| `printpdf` + `svg2pdf` | 0.12.8 / 0.13.0 | 2026-09-09 | измерено **+5.99 MiB** в release, +5.12 MiB в сборке как для dist; статически; текстовые операции используют встроенные шрифты просмотрщика PDF, поэтому файлы шрифтов не поставляются | вторая вёрстка по построению: сырые потоки `Op`, без переноса строк — перенос ложится на rtok; `printpdf` 0.12 жёстко зависит от `azul-layout` 0.0.16 (своего текстового движка), который rtok почти не использует; `svg2pdf` нужны шрифты для SVG `<text>` (`fontdb`, системные шрифты) |
| рендеринг через браузер (headless Chrome/Safari, `wkhtmltopdf`, `weasyprint`) | — | 2026-09-09 | идеальная вёрстка, HTML и PDF из одного источника по определению | не проходит критерий (2): зависимость времени выполнения от стороннего инструмента, запускаемого на каждый отчёт, — это не один статический бинарник (D1, D6). Отклонён по критерию; без сборки, чисел не заявляется |

С графиками решение то же. `plotters` 0.3.7 (бэкенд SVG, `ttf`, `all_series`,
`all_elements`) показал **+0.24 MiB** и даёт тот же SVG, который формат HTML встраивает inline, а
PDF внедряет, — один график, три формата. JS-библиотека графиков делает HTML единственным настоящим
форматом: постраничный PDF не может внедрить живой JS, поэтому два других формата получают скриншоты или ничего.

## Измерено (2026-09-09, macOS arm64, rustc 1.97.1 через mise)

В каждом черновом проекте есть `[profile.release] strip = "symbols"` — строка, которую P17 добавила в релизный
профиль rtok, — поэтому приросты сравниваются с сопоставимым. База — hello без зависимостей;
прирост — честная стоимость каждого кандидата. Размеры — байты из `stat -f%z`.

| Черновик | Бинарник | Байты | Прирост относительно hello | Команда |
|---------|--------|------:|---------------:|---------|
| `/tmp/rtok-t22-hello` | база | 341 488 | — | `mise exec -- cargo build --release --manifest-path /tmp/rtok-t22-hello/Cargo.toml` |
| `/tmp/rtok-t22-typst` | typst 0.15.1 + typst-layout + typst-pdf + typst-assets 0.15.1 (шрифты) | 44 696 240 | **+44 354 752 B (+42.30 MiB)** | `mise exec -- cargo build --release` в черновике (1 мин 04 с реального времени) |
| `/tmp/rtok-t22-printpdf` | printpdf 0.12.8 + svg2pdf 0.13.0 (+usvg 0.45.1, azul-layout 0.0.16) | 6 619 104 | **+6 277 616 B (+5.99 MiB)** | `CARGO_TARGET_DIR=/tmp/rtok-t22-target-printpdf mise exec -- cargo build --release --manifest-path …` |
| `/tmp/rtok-t22-printpdf` | то же, `[profile.dist]` (thin LTO, 1 cgu) | 5 711 904 | **+5 370 416 B (+5.12 MiB)** | то же с `--profile dist` (2 мин 28 с) |
| `/tmp/rtok-t22-plotters` | plotters 0.3.7, бэкенд SVG | 591 136 | +249 648 B (+0.24 MiB) | `CARGO_TARGET_DIR=/tmp/rtok-t22-target-plotters mise exec -- cargo build --release --manifest-path …` |

Каждый черновой бинарник был запущен, а не только слинкован: бинарник с typst скомпилировал одностраничный отчёт с
таблицей (`report.pdf`, 22 236 B, 17 внедрённых шрифтов); бинарник с printpdf записал текстовую страницу
(`report-printpdf.pdf`, 1 415 B) и график через svg2pdf (`chart-svg2pdf.pdf`, 13 550 B); бинарник с
plotters записал линейный график (`savings.svg`, 15 896 B). Из прироста typst ~9.6 MiB — это
шрифты `typst-assets` (`du -sk`, 9 780 KB), внедрённые именно для того, чтобы бинарник оставался
самодостаточным; сборка со шрифтами из системы была бы меньше, но вернула бы зависимость
времени выполнения.

## Выбор

**`printpdf` + `svg2pdf` для PDF; SVG из `plotters` для графиков.** Это единственный кандидат,
который не уводит число P17 из поля зрения: +5.99 MiB в release / +5.12 MiB в сборке как для dist, измерено. Механизм:
`src/report/pdf.rs` обходит ту же модель D23, что и другие представления, и раскладывает её
через низкоуровневый поток `Op` из printpdf (встроенный Helvetica, страницы A4); SVG графика, созданный
plotters, — те же байты, которые HTML встраивает inline, — проходит через `svg2pdf::to_pdf` на
страницу. Набор разделов, числа и их порядок берутся из модели, поэтому PDF не может
расходиться с HTML; от формата зависит только вёрстка (D24).

По критерию (3) typst выглядит победителем, но им не является, если HTML из T22.2 зафиксирован: формат HTML —
это один самодостаточный файл, сгенерированный из модели (inline CSS, inline SVG, открывается
из `file://`). Если пропустить его через экспорт HTML в typst, каждый формат платил бы за typst
42 MiB; если сохранить HTML из T22.2, то model→HTML и model→typst→PDF всё равно остаются двумя вёрстками.
Единственное, что оба формата действительно разделяют, — SVG графика — разделяется и при выбранном здесь варианте.

## Отклонено

- **typst как библиотека** — измеренная стоимость. +42.30 MiB к бинарнику, который сегодня весит 18.27 MiB;
  прогноз ниже даёт dist-сборку около 62 MB, ~3.5×, что не проходит условие P17
  при любом прочтении её цели. Критерий (3) его не спасает (см. выше).
- **Рендеринг через браузер** — критерий (2): headless-браузер — это зависимость времени выполнения
  и сторонний инструмент на пути отчёта (D1, D6). Отклонён без сборки; заявлений о размере
  для него не делается.
- **JS-библиотека графиков** — делает HTML единственным настоящим форматом, а PDF — второсортным;
  второй язык, встроенный в самодостаточный файл ради байтов, которыми не может воспользоваться ни один другой формат.

## Арифметика бюджета

Измерено, по записям: релизная база P17 — 19 157 712 B (18.27 MiB, 2026-09-04)
и dist-бинарник 17.4 MB (2026-09-07). Измерено здесь: приросты победителя в таблице выше.
**P17 не публиковала предел в байтах**, поэтому условие проверки «остаётся в пределах бюджета P17» применяется как
арифметика над записанными числами, опубликованная здесь, а настоящее измерение со слинкованным рендерером
ожидается, когда T22.3 его слинкует:

- прогноз для dist: 17.4 MB + 5.37 MB (прирост 5.12 MiB) ≈ **22.8 MB, +31 %** к записанному
  dist-бинарнику — тот же класс размера, который опубликовала P17, для единственного формата, который не может существовать
  без движка вёрстки в бинарнике.
- прогноз для release: 19 157 712 + 6 277 616 = 25 435 328 B (24.26 MiB), +32.8 %.
- typst для сравнения (арифметика, сборка dist не делалась): 17.4 MB + 44.35 MB ≈ **61.8 MB**,
  ~3.5×. Вне бюджета при любом прочтении; именно поэтому побеждает меньший кандидат.

**Слинковано, измерено 2026-09-10** (macOS arm64, rustc 1.97.1 через mise, релизный профиль с
`strip = "symbols"` из репозитория, изолированные целевые каталоги): до T22.3 `bcc5da0` 21 089 200 B
(20.11 MiB) → T22.3 `ba4c90a` 23 262 832 B (22.19 MiB; собрано на `df68bf4` — два коммита
над `ba4c90a` затрагивают только `.gitignore`/`plan.md`/`roadmap.md`) — прирост **+2 173 632 B
(+2.07 MiB, +10.3 %)**, на 2 172 496 B меньше прогноза в 25 435 328 B. Команды:
`git worktree add --detach /tmp/rtok-t223-base bcc5da0`, затем в каждом дереве
`CARGO_TARGET_DIR=$PWD/target mise exec -- cargo build --release`; размеры —
`stat -f%z target/release/rtok`. Прирост существенно меньше черновых +5.99 MiB,
что срабатывает как первое условие фальсификации этой страницы и требует переоценки: черновик оценивал
printpdf + svg2pdf + usvg относительно hello без зависимостей, а итоговое дерево линкует только printpdf с
его жёсткой зависимостью `azul-layout` (`svg2pdf`/`usvg` отсутствуют в `Cargo.lock`; графики
рисуются нативно, `done.md` T22.3), и реальный набор фич rtok разделяет с этим деревом больше, чем
база hello. Проверка выдерживается на измеренных числах — +10.3 % к бинарнику до отчёта,
тот же класс размера, — и релизный бинарник рендерит PDF для пустого хранилища (25 954 B,
`%PDF-1.3`…`%%EOF`) от начала до конца.

Если когда-нибудь в проверку впишут предел, сверять с ним нужно именно +31 % —
и запасной вариант — не typst, а отказ от постраничного PDF или урезание зависимости printpdf
`azul-layout` (printpdf 0.8 появился раньше неё и, вероятно, стоил бы меньше; здесь
не измерено, отмечено как рычаг).

## Что опровергло бы выбор

- Слинкованная сборка T22.3 с приростом, существенно выходящим за +5.0–6.3 MiB к бинарнику до отчёта
  (реальный набор фич rtok может тянуть иные пути, чем черновик). Тогда — переоценка или отказ от
  постраничного PDF. Сработало 2026-09-10, ниже диапазона (+2.07 MiB): переоценено в разделе «Арифметика
  бюджета», постраничный PDF сохранён.
- Требование к отчёту, которое printpdf не может выполнить, если rtok не обзаведётся собственным переносчиком строк или
  шейпером (текст CJK, неразрывные строки шире страницы). Тогда честный ответ — упрощённый PDF
  (обрезанная ячейка, альбомная таблица), а не 42 MiB движка вёрстки.
- Зависимость `fontdb` в svg2pdf от системных шрифтов ломает текст графиков на голом раннере Linux. Тогда
  один шрифт внедряется в `fontdb`, а его байты измеряются в T22.3, или текст графиков
  заменяется числами вне графика.
- Урезанная сборка typst с необязательными шрифтами, измеренная в пределах прироста победителя, — тогда критерий
  (3) возвращает решение к typst.

## Рекомендации (T22.5)

Правило **top-sinks** (T59.8) ранжирует десять крупнейших потребителей токенов по `Measurement.before_bytes` — пути к файлам для `read`, основы команд для `cmd`, `server/tool` для обёртки MCP — и называет переключатель rtok, который сократил бы каждый из них (`[plugins.read] default_mode`, правило `[stem]` или `rtok mcp --`).
