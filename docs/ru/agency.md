# Agency: кроссплатформенный продукт

Это основной текст об **agency** для агентов, работающих над rtok.

## Платформы

**rtok — кроссплатформенный продукт.** Поддерживаемые платформы — ровно
**Windows**, **macOS** и **Linux**. Он **обязан** и дальше поддерживать все три
как полноценные целевые платформы.

**Не** добавляйте другие платформы — ни в код, ни в документацию, ни в CI, ни в релизы. Не упоминайте
другие операционные системы как поддерживаемые, запланированные или необязательные.

Относитесь к каждому изменению так, будто оно будет работать на Windows, macOS и Linux:

- Пути, переменные окружения, оболочки, концы строк и раскладка установки различаются между
  этими тремя; не полагайтесь на чисто Unix-привычки (`~/.…`, `sh`, символические ссылки,
  `chmod`) без пути для Windows.
- Хуки, MCP и `rtok proxy` — одни и те же интерфейсы на Windows, macOS и
  Linux; пути установки у хостов и поведение при повторном открытии GUI всё равно нужно покрыть на
  всех трёх (см. [agents.md](agents.md)).
- Релиз поставляет `x86_64-pc-windows-msvc`, `aarch64-apple-darwin` и
  `x86_64-unknown-linux-gnu` (см. [release.md](../release.md)). Предпочитайте исправления, которые
  сохраняют эту матрицу зелёной; не убирайте и не объявляйте «мягко устаревшими» Windows, macOS или
  Linux без явного решения пользователя.
- CI, документация, скрипты и примеры, которые работают лишь на части этих трёх платформ,
  считаются незавершёнными, пока недостающие из Windows / macOS / Linux не
  охвачены (или пока пробел не задокументирован как известное ограничение с отслеживаемой
  задачей на продолжение).

## Чем это не является

Этот файл **не** матрица «хост × модуль» ([agents.md](agents.md)) и не
замена корневого `AGENTS.md` (рабочий процесс, проверки, правила fail-open). Он
фиксирует платформенный контракт, который эти агенты обязаны соблюдать.
