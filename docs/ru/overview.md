# Обзор

rtok — это один бинарник на Rust, который сокращает количество токенов, сжигаемых ИИ-агентом для программирования. Каждый
метод сокращения токенов — это плагин за единым трейтом, и к этим плагинам ведут три
интерфейса:

| Интерфейс | Точка входа |
|---------|-------------|
| Хуки Claude Code | `rtok hook <event>` — JSON на stdin, JSON на stdout |
| MCP-сервер | `rtok mcp` — `read`, `search`, `tree`, `expand`, `mem_*`, инструменты графа |
| API-прокси | `rtok proxy` — промежуточный узел для `ANTHROPIC_BASE_URL` / `OPENAI_BASE_URL` |

> [!WARNING]
> **Статус: v0.0.1.** Все десять плагинов реализованы во всех трёх интерфейсах, вместе с
> измерением, происхождением настроек, экспортом OTLP и веб-панелью. Не сделано
> то число, которое действительно важно: закоммиченный A/B-бенчмарк запускался только офлайн, поэтому он показывает
> нули для обеих конфигураций. Сегодня rtok утверждает «измеримо», а не «дешевле».

## Зачем он нужен

Типичная настройка Claude Code нагромождает несколько инструментов, каждый из которых сжимает вывод Bash, кеширует
чтения и внедряет контекст при старте сессии, — и каждый заявляет экономию 60–95 %, которую никто
не измеряет от начала до конца. При измерении такой набор экономит 3–40 % и стоит примерно 3 K внедрённых
токенов за ход.

rtok заменяет этот набор одним бинарником, который работает как один хук на событие, предоставляет одиннадцать MCP-инструментов
за ~143 токена описаний на ход вместо ~8 600 на девять серверов, стоит одним
промежуточным узлом прокси, который записывает реальный `usage`, и ведёт одну таблицу измерений, чтобы `rtok stats` мог
сказать, что на самом деле изменилось. Полный разбор по каждому инструменту, включая то, где rtok отстаёт, —
в [Сравнении](comparison.md).

Каждый плагин написан с нуля в этом репозитории. rtok никогда не запускает, не линкует и не читает
инструменты, которые он заменяет.
