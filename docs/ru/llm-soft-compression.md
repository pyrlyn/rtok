# Мягкое сжатие через LLM (P28)

**Статус: Later / дизайн + экстрактивный вариант выпущены; LLM-ветка всё ещё закрыта проверкой.**

Источники замысла: `ideas.md` (I-21, “LLM soft compression (P28)”),
`plan.md` / `done.md` **P28** (T28.0–T28.2),
`src/plugins/compress/PLAN.md` (обзор D15), `roadmap.md` Later,

## 1. Что здесь означает «мягкое сжатие»

В rtok **мягкое сжатие через LLM** — это **необязательное, измеряемое, начинающееся с архивации
переписывание текста в контексте** (обычно старых тел `tool_result`, уже
доступных через `expand <id>`), выполняемое **вызовом модели** (или небольшим
специализированным компрессором), а **не**:

- квантизация KV-кеша / активаций внутри GPU провайдера
- attention sinks, скользящее окно или масштабирование RoPE в стеке обслуживания
- автокомпакция хоста (`PreCompact` / `preCompact`) — это территория T58.2 /
  контрольных точек
- **детерминированная экстрактивная** сводка, уже выпущенная в
  `plugins.compress` (T28.2 / T127)

«Мягкое» = **представление** в промпте может отбрасывать или перефразировать байты;
**жёсткий** контракт (D4) хранит оригинал в `~/.rtok/archive/`, поэтому
`rtok expand <id>` / MCP `expand` восстанавливает невоспроизводимые источники.

### Уже выпущено (не пункт Later)

| Компонент | Поведение сегодня |
|-------|-----------------|
| Архив без потерь + `expand` | Всегда включён для отфильтрованных/заархивированных данных |
| Экстрактивный ранжировщик `plugins.compress` | По умолчанию **включён** (`enabled = true`); работает только при `proxy.mode = "compress"`; без сети / без LLM; строки `Measurement` |
| Переписывания в прокси с живой зоной / сохранением кеша | Старые результаты инструментов уменьшаются без перетряхивания system/tools/живой кромки (`docs/prompt-cache.md`) |
| Режимы сжатия вывода / прозы | Экстрактивный + в стиле caveman (`modes`, сравнительные бенчмарки) |

Пункт по-прежнему отслеживается в `ideas.md` (I-21) как **To add**, потому что
**LLM-ветка** (класса LLMLingua или извлечение наблюдений в стиле claude-mem
за явным флагом, Gate P28) — **не** экстрактивный путь по умолчанию.
T28.2 внедрил экстрактивную реализацию и отложил LLM-извлекатель
наблюдений для памяти.

## 2. Обзор подходов (что подходит для среды прокси / агента)

rtok — промежуточный слой: хуки, MCP и особенно **`rtok proxy`** на синхронных
чат-протоколах. Он **не** владеет KV-кешем или сэмплером модели. Подходы
делятся на три группы.

### A. Реалистично для rtok (уровень HTTP / архива)

| Подход | Идея | Применимость | Оговорка |
|----------|------|-----|--------|
| **Семантическая сводка после архивации (выбрано)** | После архивации без потерь заменить блок в контексте структурированной сводкой (тип / заголовок / факты / файлы); `expand` сохраняет оригинал | **Основной механизм P28** (`compress/PLAN.md`) | Стоит токенов компрессора; риск качества для кода/диффов |
| **Экстрактивное сохранение/отбрасывание токенов/фрагментов (класса LLMLingua-2)** | Небольшой классификатор оценивает токены; малоинформативные фрагменты отбрасываются | Полезно как **локальная / офлайн**-ветка или база для бенчмарка; идея уже рассмотрена; сам пакет Microsoft отклонён (D6) | Без обратного указателя на архив не без потерь; слабо работает с идентификаторами |
| **Извлечение наблюдений → `memory`** | LLM после инструмента пишет заметки; постепенное раскрытие | Необязательная половина T28.2; связано с I-73 / I-79 “LLM half stays P28” | Неверные факты отравляют поиск в памяти; по умолчанию выключено |
| **Хуки компакции хоста + id архива** | Переживают суммаризацию провайдером | T58.2 (отдельная карточка); дополняет мягкое сжатие | Сам по себе байты не уменьшает |
| **Маршрутизация моделей для вызовов компрессора** | Дешёвая модель для суммаризации / классификации | Ортогональный рычаг (`docs/model-routing.md`); использовать для расходов **компрессора**, а не модели агента для кода | Нужна проверка маршрутизатора; не смешивать с Batch/Flex |

### B. Смежное, но не «мягкое сжатие»

| Подход | Почему это другой рычаг |
|----------|-----------------------------|
| **Batch / Flex** | Меняет то, *когда / по какому тарифу* идут те же байты (`docs/batch-flex.md`). Мягкое сжатие меняет то, *сколько* байтов промпта отправляют синхронные протоколы. |
| **Sticky-префикс кеша промпта** | Мягкое сжатие **никогда** не должно переписывать system / tools / живую кромку (T14.5 / D). |
| **Семантический кеш ответов (P31)** | Кеширует **ответы**, а не сжимает промпт; риск ложных попаданий. |
| **TOON / форматтеры cmd / tools_rewrite** | Детерминированные переписывания без потерь или по белому списку — уже есть в v0.1. |

### C. Вне охвата rtok (внутренности обслуживающей модели)

| Подход | Почему rtok не может выпустить это как плагин |
|----------|-------------------------------------|
| **Сжатие / вытеснение KV-кеша** | Живёт в vLLM / TensorRT-LLM / у провайдера; rtok никогда не видит тензоров |
| **Квантизация активаций / весов для инференса** | Обслуживание на этапе развёртывания; не промежуточный слой прокси |
| **Attention sinks / скользящее окно / LongRoPE** | Архитектура модели / конфигурация обслуживания |
| **Спекулятивное декодирование / Medusa** | Задержка, а не экономия токенов промпта в протоколе агента |

Если провайдер предоставит флаг API для «сжатого контекста», рассматривайте его как
эксперимент **Wire prepare** с Measurement — это всё равно не мягкое сжатие KV
внутри rtok.

## 3. Какой механизм сохранить (решение)

Подтверждаем `src/plugins/compress/PLAN.md`:

1. **Ветка без потерь** — без изменений, всегда доступна.
2. **Экстрактивная ветка** — выпущена; детерминирована; по умолчанию включена при
   `proxy.mode = "compress"` и `plugins.compress.enabled`.
3. **LLM-ветка (Later)** — по умолчанию **выключена**; только после появления строки архива;
   только при соответствии критериям архива (например, старше N ходов или больше
   предела размера); никогда не трогает закешированный префикс; пишет `Measurement` с
   `bytes_in` / `bytes_out` / `tokens_spent` / `plugin = compress` (или
   `memory` для извлекателя наблюдений).
4. **Gate** — `rtok bench` в стиле P9: **стоимость одной пройденной задачи ≤** базы
   без потерь (с учётом токенов компрессора); доля прохождения не должна падать;
   `expand` восстанавливает невоспроизводимые оригиналы.

Отклонено (по-прежнему): обёртки над Microsoft LLMLingua / воркером claude-mem /
headroom (D6); LLM, включённая по умолчанию; обрезка без архива; переписывание префикса.

## 6. Риски и фальсификаторы

1. **Стоимость одной пройденной задачи растёт** с учётом токенов компрессора → не выпускать.
2. **`expand` не срабатывает** на невоспроизводимых tool/read/diff → провал D4; блокировать.
3. **Заявленная экономия без `Measurement`** → D1; такой экономии не существует.
4. **Сброс кеша промпта** из-за переписывания system/tools/живых ходов → регрессии долей попаданий в `docs/prompt-cache.md`.
5. **Качество текста в форме кода** (research.md §6.9 / уроки caveman) → в Фазе 1 требуются golden-фрагменты «обязательно сохранить».
6. **Путаница между экстрактивным (включён) и LLM (Later)** в документации/маркетинге → этот файл и именование в `ideas.md`.
